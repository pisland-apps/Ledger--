第一节 这是一款什么样的 App

完全离线的个人/家庭记账 App：数据只在本机，支持多种账户、多位成员和加密锁。

约 1 分钟读完

Ledger 是一个安装到手机主屏幕、完全离线运行的个人/家庭记账应用：

  • 所有数据只保存在本机浏览器本地数据库里，不会上传到任何服务器；

  • 提供多种报表和图表，帮助你看清收支和资产分布。

第二节 首次使用：设置密码锁

第一次设置密码、开启指纹/人脸解锁，以及忘记密码的后果。

约 1 分钟读完1 个小节

第一次打开 App 时会看到 "Set an App Passcode" 设置页：

  1. 输入一个密码（至少 4 位），再输入一次确认；
  2. 点击 "Create & Continue"。
没有找回机制

这个密码同时是数据加密的密钥来源（PBKDF2 + AES-GCM）。忘记密码 = 无法解密数据，没有"找回密码"这一说——只能在解锁页点 "Forgot passcode? Reset app data" 清空重来。请务必把密码记在安全的地方。

设置完密码后，系统可能会询问是否开启指纹/人脸快捷解锁（需要设备支持，且只在 HTTPS 环境下可用，本地 file:// 打开时会自动隐藏这个选项）。

之后每次打开 App

  • 会看到解锁页，输入密码，或点击 "🫆 Unlock with Biometrics" 用指纹/人脸解锁；
  • 页面下方有一个数字键盘方便手机上快速输入纯数字密码（也可以直接点输入框用系统键盘打字，密码不限于纯数字）；
  • 解锁页右下角有一个小版本号标签，方便确认当前运行的是哪个版本。

第四节 记一笔账（收入 / 支出 / 转账 / 工资）

收入、支出、转账；Quick Add、拆分、标签、附件；退款、报销与待收回款项。

约 8 分钟读完2 个小节

点击首页右下角 "+" 按钮，选择类型后会弹出记账表单，主要字段：

  • ✨ Quick Add（快速记账）：表单最顶部有一个自动获得焦点的输入框，可以直接打字或粘贴一句话，如"Lunch RM25 KFC"或"咖啡15块上周五"，App 会完全离线解析出金额、（相对）日期、描述，并尝试匹配历史记录或内置关键词猜出分类——金额/日期/描述解析出来直接填入下方表单，分类则以候选圆片形式出现，点一下确认（只在和当前表单收入/支出类型一致时才会出现候选）；命中历史记录时账户也会一并预选；
  • 金额（Amount）：支持右侧的计算器/数字键盘小图标，方便直接在里面做加减乘除；
  • 分类（Category）：点击弹出的分类选择器（自定义弹窗，字体大小可读性更好）；支持"拆分（Split）"——一笔交易同时记到多个分类，点 "+" 增加拆分行；退款（Refund）交易的分类默认预填原支出分类，但同样完整展示所有支出分类供你自由改选，不再锁定；
  • 标签（Tags）：表单底部字段，用于给一趟旅行/一次报销的所有相关交易打上同一个标记。输入几个字即可模糊匹配已有标签（搜索范围是标签名任意位置，不只是开头），没有匹配项时会出现 "+ Create tag" 一键创建并附加；每笔交易可挂多个标签，以小圆片形式展示，可随时移除；转账交易不显示此字段。标签可以提前在 Setting → 🔖 Manage Tags 里建好，也可以记账时随手新建；交易详情（Quick View）的 "Tags:" 行同样有一个 "+ Add" 按钮，可弹出标签选择器（勾选式多选、支持搜索/新建），不必绕回记账表单；
  • 账户 / 转入账户（Account / To Account）：转账类交易需要选择来源和目的账户；
  • 日期（Date）；
  • 描述（Description）：必填，输入时会自动联想你历史上用过的描述（模糊匹配，输入片段即可命中，匹配部分会高亮）；
  • 备注（Notes）：可选；
  • 附件（Attachments）：可拍照或从相册/文件选择照片、PDF，一笔交易可加多个附件，之后可在交易详情里预览/下载；
  • 涉及外币转账时，可开启"Currency Conversion"手动填汇率或实际到账金额，二者互相联动计算，且一旦记录就永久锁定，不受后续汇率表变化影响；
  • 涉及定期存款（FD）账户时，表单会显示利率、起息日、期限（月）、到期日等专属字段，到期日自动计算。

填好后点击 "Commit Entry" 保存。编辑已有交易时，表单底部会出现红色 "🗑 Delete Entry" 删除按钮。

还没到付款日？先存成"计划"

新建 Income/Expense 时，"Commit Entry" 旁边还有一个 "🕒 Save as Planned" 按钮，以及一个 "🔁 Repeat" 开关——用来记一笔还没发生、以后才要付的账单（房租、订阅等），不会立即影响余额。详见第十七节「计划付款与周期扣款」。

用标签统计一整趟旅行的花费

例如出国旅行：先建一个"日本旅行 2026年8月"标签，记账时不管这笔钱是机票、住宿还是餐饮（各归各的分类），都顺手挂上这个标签。之后在报表里打开 Spending by Tag（见第七节），就能一次性看到这趟旅行不分类别、不分月份的总花费。

退款与报销（Refund / Reimbursement）

交易的 Options 弹窗里，原来的 "🔄 Refund" 已拆分为两个按钮：↩️ Refund（普通退款）与 💰 Reimbursement（报销）。两者打开同一张表单、保存逻辑完全一样，数据库里只用 refundReason 字段区分显示的徽章文字，互不影响原有的退款计算规则。

已报销/已退款的支出，其原交易行会自动显示一个绿色的 "✅ Claimed"（或 "✅ Refunded"）徽章，点击可直接跳转到对应的报销/退款记录。

一键打开报销表单

挂有标签的支出会在交易行上显示一个可点击的 🔖 标签徽章（Dashboard、账本列表、Spending by Tag 报表里都有）。点一下该徽章会直接打开预填好金额/账户/分类的 Reimbursement 表单，不再是先跳去 Spending by Tag 报表。表单里还会多出一个开关"🔖 Remove '标签名' tag from the original transaction"（默认开启）——保存报销时如果开着，原支出上的这个标签会被自动摘掉，无需再回去手动编辑一次；如果是分批结清（部分报销），可以先关掉这个开关保留标签。

也可以在交易详情（Quick View）里直接管理标签：详情页有一行 "Tags:"，每个标签旁都带一个小 "✕"，点了就能单独移除某个标签，不必绕道报销表单。

垫付出去的钱，怎么跟踪？先选方法

你的情况 推荐做法 这笔钱算不算"支出"
对方会单独转一笔钱还你（代付公司费用、借出去的钱） 方法一：🧾 Lend / Claim 不算——在账本里它只是"资产之间的转移"（转入 Claims Receivable）
报销款会并入工资一起发（例如公司手机费津贴），你只想记住"哪几笔还没收到" 方法二：用两个标签跟踪 算——就是一笔正常支出，标签只是"状态贴纸"

方法一：待报销支出——Claims Receivable（应收报销款）

适合：对方会单独转账还你，且你希望这笔垫付不算作"花掉"的支出。

首页 "+" 悬浮按钮和任意账户 Activity 页面的 "+" 里都有一个 🧾 Lend / Claim 快捷入口：记一笔待报销/待收回的支出（例如代垫的公司费用、借出去的钱），系统会把这笔钱转入一个叫 "Claims Receivable"（应收款） 的资产类账户（归在 Other Assets 分组），并自动挂上 "Pending Claim" 标签。这类支出会天然不计入报表和预算——因为在账本结构上它属于"资产之间的转移"，而不是真正花掉的支出。

  • 首页 Tag Reminders 小组件和 Spending by Tag → Pending Claim 报表都会显示当前有多少笔、共多少钱还没收回；
  • 钱到账后，回到某一笔上点 🔖 标签徽章即可打开 Reimbursement 表单结清；

  • 🧾 Settle Multiple Bills as One Claim（只在 Spending by Tag → Pending Claim 视图下出现）：适合"一笔汇款同时结清好几笔代垫款"的场景。点开后是一份待结清账单的勾选清单（默认全选，可取消不在本次结清范围内的），填入实际收到的金额、日期和入账账户，页面会实时显示：

    • 所选账单的合计；
    • ⚠️ 短收（实收 < 账单合计）——会记一笔普通支出，类别可自选（默认 "Other Expenses"）；
    • 🎉 多收（实收 > 账单合计）——会记一笔普通收入，类别可自选（默认 "Other Income"）。

    保存后会生成一笔报销收入记录（Notes 里列明每笔账单的日期/描述/金额），短收/多收部分单独另记一笔正常收支（会计入报表和预算），所有被结清的账单同时摘掉 "Pending Claim" 标签。若勾选的账单涉及不同币种，会提示分批分别结清，暂不支持跨币种一次性汇总。

方法二：用两个标签跟踪（适合报销款并入工资发放）

适合：公司让你先自己垫付（例如手机话费），之后把这笔钱作为津贴并入工资一起发放，而不是单独转账给你。这种情况不需要动 "Claims Receivable" 账户，只要用两个标签当作"状态贴纸"，就能一眼看出哪几笔还没收回、哪几笔已经收到。

只做一次：建好两个标签

  1. Setting → 🔖 Manage Tags，新建两个标签。名字用"事项 + 状态"的写法，一看就懂，例如：
    • 手机费-待报销（已垫付、已提交单据，钱还没到）
    • 手机费-已报销（津贴已随工资入账）
  2. 点 ✏️ 编辑 "待报销" 这个标签，打开 📌 显示为 Dashboard 提醒 开关。这样首页的 Tag Reminders 会实时显示"还有几笔、共多少钱没收回"。"已报销"标签不用开。

有别的事项（网费、差旅等），照样各建一对标签就行。

每一笔的流程

  1. 垫付并提交单据——正常记一笔 Expense（如"手机话费 RM100"），在标签栏加上 手机费-待报销；有收据可以先拍照存进附件。
    • 🔖 这笔支出的标签：手机费-待报销
    • 🏠 首页 Tag Reminders：显示这一笔，笔数和总额随之增加
  2. 津贴随工资到账——记工资时，在 Salary 表单的 📱 手机报销 栏填入这笔津贴。
  3. 把标签换成"已报销"——打开那笔手机费的交易详情（Quick View），在 "Tags:" 一行点 手机费-待报销 旁的 ✕ 摘掉，再点 "+ Add" 选 手机费-已报销。
    • 🔖 这笔支出的标签：手机费-已报销
    • 🏠 首页 Tag Reminders：这一笔从提醒里消失；全部换完后，整行提醒会自动消失

一笔工资里如果同时包含好几个月的手机费，就把这几笔挨个换成"已报销"标签。

想核对时：在 Spending by Tag 报表里查看 手机费-待报销，就知道目前还有多少钱没收回；查看 手机费-已报销，就是累计已经收回了多少。

换标签时，不要点交易行上的 🔖 徽章

📊 单位信托基金使用指南（从建立到清仓）

基本流程

  1. 建账户：侧边栏 Financial Accounts → 新增账户，类型选 Unit Trust（Sub-Group 选 Unit Trust；黄金则选 Gold，见下一小节）。习惯上一家基金公司或一个投资平台建一个账户。
  2. 加基金：进入该账户 → Add Fund，填基金名称、Fund Code（可不填）、Category、Currency、Owner（可多选，联名基金选多位成员，之后才能按成员筛选）和 Current NAV（当前净值）。
  3. 记交易：在该基金点 + Transaction，选 Type、日期、份额（Units）、单价（Price per Unit）和总金额（Total Amount）；填份额和单价会自动算出总金额，填份额和总金额则会自动算出单价（Dividend (Cheque Payout) 不涉及份额，只填总金额）。Buy 要选付款的银行/现金账户，Sell 和 Cheque Payout 要选收款账户，App 会自动生成对应的转账；Dividend (Reinvest) 和 Contribution 直接把份额加回基金，不需要选账户。
  4. 更新净值：侧边栏 Daily NAV Update → 📊 Unit Trust 标签 → 填当天净值 → Update All Prices。市值 = 份额 × 最新净值；不更新净值，市值就停在上一次填的数字。
  5. 看结果：账户页的 Fund Holdings 表看单个账户，侧边栏 Reports → Unit Trust Portfolio 看全部基金合并后的总览。

五种交易类型

类型 份额 现金 对数字的影响
Buy 增加 从你选的账户转入 计入 Invested
Sell 减少 转入你选的收款账户 计入 Recovered
Dividend (Reinvest) 增加 没有新增现金 不计入 Invested，全部体现在 P/L
Dividend (Cheque Payout) 不变 派息现金转入你选的账户 计入 Recovered
Contribution（供款） 增加 没有新增现金 不计入 Invested，全部体现在 P/L

每个数字是什么意思

数字 含义
Value（市值） 份额 × 当前净值
Total Invested 历史上所有 Buy 的累计金额，卖出后也不会减少
Recovered 已经拿回手的现金：Sell 所得 + Cheque Payout 派息
Current Invested Total Invested − Recovered，即"净投入"：投进去的钱减去已经拿回来的钱
P/L（盈亏） Value + Recovered − Total Invested，包含已经落袋的盈亏和还没卖的浮动盈亏
Return（收益率） P/L ÷ Total Invested，分母是 Total Invested，不是 Current Invested
Annualised（年化） 从第一笔交易起算到今天；持有不足约一个月时显示 "-"

因为 Value + Recovered − Total Invested = P/L，所以把 Recovered 移到另一边就得到：Current Invested + P/L = Value。Unit Trust Portfolio 卡片就是围绕这条等式设计的。

Unit Trust Portfolio 卡片怎么读

  • 左上大字是组合市值（Portfolio Value）；右上徽章是收益率，绿色 ▲ 代表盈利、红色 ▼ 代表亏损，下方小字写明 "return on total invested"，提醒你分母是 Total Invested。
  • 中间一行是 = Current Invested + Profit / Loss，两项相加正好等于上面的市值。
  • 分段条：整条代表 Total Invested（标题行 BAR = TOTAL INVESTED 右侧是金额）。紫色段是 Current Invested，灰色段是 Recovered，下方两行图例写着各自的金额和占比。电脑端把鼠标放在色段上会显示说明；手机上没有悬停提示，看下方图例即可。
  • 多币种基金会先按汇率换算成基准货币（如 MYR）再合计，所以等式对多币种同样成立。
  • 卡片颜色全部跟随当前主题，浅色、深色和各种背景主题都会自动适配。
Current Invested 是"净投入"，不等于"目前持有部分的成本"

举例：基金 A 投入 1,000 仍在持有；基金 B 投入 5,000，全部赎回拿回 6,000。合计 Current Invested = 1,000 + (5,000 − 6,000) = 0，尽管基金 A 里其实还有 1,000 的本金。原因是基金 B 赚的 1,000 已经拿走，会把整体的净投入抵掉。这个口径保证 Current Invested + P/L = Value 永远成立，但如果你有已清仓且盈利的基金，请不要把它理解为"现在还有多少本金在基金里"。账户表格里每只基金各自的 Current Inv. 一列也是同样的算法。

全部赎回（清仓）一只基金

这个 App 没有单独的"关闭基金"按钮，全部赎回就是记一笔 Sell：

  1. 进入该基金 → + Transaction → Type 选 Sell。
  2. Units 填当前持有的全部份额（从 Fund Holdings 表的 Units 列抄下来）；Total Amount 填实际到手的金额（已扣手续费的净额）。
  3. 选收款的银行/现金账户，保存。赎回前如果还有未入账的派息支票，另外记一笔 Dividend (Cheque Payout)。

保存后：基金份额变为 0，收款账户增加，基金的最终盈亏（已实现）= 赎回款 + 派息 − 总投入。

  • 已清仓基金会折叠：份额为 0 且买入过的基金，在 Fund Holdings 和 Unit Trust Portfolio 的 Fund Detail 里合并成表格底部一行 ▸ 1 closed fund · Realized P/L +RM… · tap to show，点一下展开，再点一下收起。这是全 App 共用的一个开关，每台设备各自记住你的选择，默认收起。折叠只是不列出，合计仍然包含它们。刚新增、还没有买入的基金不会被当成已清仓。
  • 份额要填准：App 不检查 Units 是否超过持有量。填少了，剩下的份额还会按净值留在账上；填多了，份额只会减到 0，但这笔交易仍记着多填的数字。
  • 不要删除已清仓的基金：Delete Fund 只删基金记录，交易保留，但 Unit Trust Portfolio 只统计还存在的基金，删除后它的投入、回收和已实现盈亏会从总览里消失。想保留历史，就让它留在 0 份额状态。
  • 年化收益会逐渐下降：持有年数是从第一笔交易算到今天，而不是算到赎回日，所以已清仓基金的 Annualised 会随时间自动变小；判断它的最终表现，请看 Return 和 P/L。
表格里的两套数字

Fund Holdings 和 Fund Detail 的 Invested 是累计 Buy，Current Inv. 是 Invested − Recovered，二者加上 P/L 的关系不同：单只基金一定满足 Current Inv. + P/L = Value，而不是 Invested + P/L = Value。两个表格的悬停提示（鼠标放在列标题上）也写明了这一点。

🪙 记录实物黄金（金条 / 金饰 / 银行黄金账户）

黄金在 App 里就是一只类别为 🪙 Gold 的基金（Fund）：份额单位换成克（g），"净值"换成每克价格（RM/g），其余——投入成本、已回收金额、盈亏、买卖自动生成转账——全部沿用基金持仓的算法，不需要另外学一套操作。银行黄金账户（如 Maybank GIA、PBB GIA）的记法完全一样：一家银行一个账户，每种纯度/来源一只持仓。

建立与买入

  1. 建账户：侧边栏 Financial Accounts → 新增账户，类型选 Unit Trust，Sub-Group 选 Gold，账户名例如 "Physical Gold"。这样账户列表会显示 🪙 Gold 徽章，净值报表里也会单独列出一行 Gold。
  2. 加持仓：进入该账户 → Add Fund → Category 选 🪙 Gold。名称按实物填写（如 "999 Gold Bar 10g"、"916 Bracelet"），Purity / Source 一栏填纯度或来源（999、916、Maybank GIA 等）。不同纯度、不同品项各建一只持仓，成本和价格互不混算。
  3. 记买入：在该持仓点 + Transaction → Type 选 Buy，填 Grams（克数） 和 Total（实际付出的总金额），Price per Gram 会自动算出；再选付款的现金/银行账户（转账来源）。
  4. 设今日价格：在 Add/Edit Fund 里把 Today's Price (RM / gram) 填成金店/银行今天愿意回购的每克价格，而不是零售卖价。
  5. 卖出：+ Transaction → Type 选 Sell，填克数和实际收到的总金额，选收款账户。

日常更新价格

侧边栏 Daily NAV Update → 点 🪙 Gold 标签，只显示黄金持仓；此时点 "Update All Prices" 只会保存黄金的价格，不会碰到基金净值（反过来选 📊 Unit Trust 也一样）。History 视图同样跟随当前标签：选 Gold 只看黄金列，没有更新记录的日期行会自动隐藏。每只黄金持仓旁会显示 "priced X d ago" 提示上次更新价格是几天前，超过 2 天变红，提醒你价格可能已过时。

溢价和工钱会显示成"浮亏"

Total 填的是你实际付出的全部金额（含溢价、金饰工钱），而今日价格填的是回购价，所以买入当天就会看到一笔未实现亏损。这是"付出的成本"与"现在变现能拿回多少"之间的真实差额，不是记错。金条的差额通常较小，金饰的工钱损耗则可能大得多。

黄金交易不能原地编辑

为避免账本悄悄偏离银行/金店的真实成交，黄金持仓的交易不能像普通交易那样修改，Type 也只有 Buy / Sell（没有股息类型）。记错了怎么办：点该交易行 → 按提示删除 → 重新记一笔正确的。

其他说明
  • 保管费、保险费、银行黄金账户年费等，作为普通支出记一笔即可，不计入黄金持仓自己的盈亏。
  • 金价目前只能手动录入，App 不会联网自动抓取（保持完全离线）。
  • 如果你的黄金账户是在 Sub-Group 出现 "Gold" 选项之前建的（当时归在 Unit Trust 下），到 Edit Account 把 Sub-Group 改成 Gold，才会显示 🪙 徽章并计入净值报表的 Gold 一行。

如何创建： 打开一笔新建 Income/Expense（支持拍照附件等所有正常字段），填好后不点 "Commit Entry"，改点旁边的 "🕒 Save as Planned"——这笔记录会被单独保存，不会影响任何账户余额。Split（拆分）交易暂不支持存为计划，开着 Split 时会有提示，需要先关掉 Split 才能保存。

查看与操作：

  • Dashboard 有一个 Planned Payments 小组件，只显示 3 天内到期或已逾期的项目（暂停中的不显示），标题可点击跳转到完整列表；
  • 侧边栏 → 🕒 Planned Payments 是完整列表页，不论到期日多远、包括暂停中的项目都会显示，但没有单独的"+"入口——新记录只能从收支表单的 "Save as Planned" 创建；
  • 点开任意一条会弹出操作菜单：✅ Mark as Paid（标记已付）/ 🗑 Delete（删除）。

🔁 Repeat（周期重复）：

  • 保存计划时勾选 "🔁 Repeat"，选择"每 N 周/月/年"重复一次（默认每 1 个月）；
  • 周期性的一条记录只会保存一份（代表"下一次到期"），不会预先生成一整串未来记录；
  • Mark as Paid 时表单会像平常一样预填好所有字段供你确认/修改后 Commit——确认后这条计划会自动前进到下一个到期日，而不是消失，之后 desc/金额/币种/账户/分类/备注 也会按这次实际提交的值同步更新到下一期（附件除外，每期从空白开始，避免带着上一次的旧收据）；也就是说房租涨价时，在确认付款时顺手改一下金额，下个月的提醒就直接是新数字；
  • 月末日期（如 1 月 31 日每月重复）遇到没有对应日子的月份（2 月）会自动钳制到当月最后一天，并记住"原始锚点日"，下个有 31 号的月份会自动回到 31 号，不会因为钳制过一次就永久漂移到别的日子；
  • Delete 对周期性记录会终止整个系列（不是只删这一次），确认提示会明确说明这一点；
  • ⏸ Pause / ▶️ Resume：只对周期性记录出现，暂停后排到列表最下面、变灰显示"⏸ Paused"，不再计入 Dashboard 的到期提醒；恢复时会自动把到期日快进到今天之后最近的一次，不会一恢复就显示"逾期很多天"；
  • Edit Series（编辑系列）：可以修改重复周期（如从"每月"改成"每 3 个月"）、手动改到期日（手动改过之后会重新设定锚点日）。

一次性（非周期）的计划只有"标记已付/删除"两个操作，Pause 与 Edit Series 只在周期性记录上出现。

第十八节 提醒事项（Reminders）

登记护照、驾照、保险等证件的续期日期，到期前在首页提醒。

约 3 分钟读完5 个小节

用来登记护照、驾照、PR 续期、信用卡有效期、保险到期这类"每隔一段时间要更新一次"的日期，快到期时在首页提醒你。所有提醒共用一份列表，不区分家庭成员。

入口：侧边栏 🔔 Reminders（和 Inventory、Planned Payments 同一层）。

新增一条提醒

Reminders 页面右下角点 "+"，填写：

字段 说明
Name 必填，例如 Passport、Driving License、PR Renewal
Category 可选，例如 Travel Document
Issue Date 可选，签发日期
Due / Expiry Date 必填，到期日
Remind Me (Days Before Due) 到期前多少天开始在首页提醒你，每条各自设置，默认 90 天
This renews / repeats 需要定期续期的勾选；勾选后出现 Renews Every (Months)，默认 12 个月。参考值：护照约 60–120 个月、驾照约 72–120、信用卡约 36、保险约 12
Notes 可选，例如证件号码

首页小组件与完整列表

  • 首页 🔔 Reminders 小组件：只显示已经进入自己提前提醒天数（或已逾期）的提醒，按到期日由早到晚排列，最紧迫的排在最前；已归档的不会出现；没有任何一条符合时整个小组件隐藏。每行右侧显示到期日和剩余时间（"Nd left" / "Due today" / "Overdue Nd"，逾期为红色）。点标题进入完整列表。
  • 完整列表页：顶部有 Active / Archived 两个标签。Active 显示所有未归档的提醒，不论离到期日多远；Archived 显示已处理完的一次性提醒（见下文）。

点一条提醒能做什么

点列表里的任意一行，会弹出操作菜单：

按钮 出现条件
✅ Mark as Renewed 勾选了 "This renews / repeats" 的提醒
📦 Archive 一次性提醒（没有勾选重复）
↩️ Restore 已归档的提醒
✏️ Edit / 🗑 Delete 所有提醒；删除前会二次确认，且无法恢复

续期流程（Mark as Renewed）

点 ✅ Mark as Renewed 后会弹出确认页，不会直接静默改日期：

  1. 页面显示 Old due date（旧到期日）；
  2. Renewal Date 默认是今天，可改；
  3. New Due Date 已预填为"续期当天 + 每隔 N 个月"，确认无误或手动改好后点 Save。

新到期日是从续期当天往后算，而不是从旧到期日往后算——所以就算拖了几天才去办，下一轮也会按实际办理日重新计时。保存后该提醒的 Issue Date 会更新为续期日，到期日更新为新到期日，并留下一条续期记录（旧到期日 → 新到期日 → 续期日）。

一次性提醒

不勾选 "This renews / repeats" 的提醒（如签证、活动报名）没有 Renewed 按钮：事情办完后点 📦 Archive，它会移到 Archived 标签；需要时可以 Restore 恢复。

只有打开 App 时才会看到提醒

App 完全离线、没有后台服务器，所以"提醒"只体现为你打开 App 时首页出现的小组件，没法在 App 关闭时向手机推送通知。建议把提前天数设得宽裕一些（默认 90 天），并养成定期打开 App 的习惯。

数据与备份

提醒数据和账本其他数据一样，加密保存在本机，并包含在 Setting → Backup & Restore 的导出/导入里。续期记录也一并保存在数据中，不过目前没有单独查看续期历史的界面。
